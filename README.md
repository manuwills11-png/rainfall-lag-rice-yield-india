# Rainfall-Lag-Aware Crop Yield Forecasting in India Using Explainable Temporal Machine Learning

A research and software engineering implementation of leakage-free machine learning pipelines for district-level crop yield forecasting across India.

## 3. Phase 2 & 3: Executed Study (time-resolved IMD weather, 16-week lags, sequence models)

Phase 1 could not test the central hypothesis because the dataset only has seasonal aggregates. Phase 2 adds **real daily IMD rainfall** (0.25° grid, validated against the dataset's own `IMD_RF`: r = 0.905), builds causal 16-week pre-harvest lags anchored to zone harvest weeks, and runs a controlled ablation.
The complete paper is [`docs/research_paper.md`](docs/research_paper.md) (also `.docx`); data provenance is in [`docs/phase2_data_sources.md`](docs/phase2_data_sources.md).

### Headline results (test 2014-2017, all computed from code)

| Question | Result |
|---|---|
| Why was Phase 1 weak (R² 0.13)? | Non-stationarity: test-year mean yield is +32 % above training; a no-weather forecast from each district's last 3 seasons already reaches **R² = 0.756 (MAE 337 kg/ha)** |
| Do 16 weekly lags beat a seasonal total? (RQ1/H1) | **No.** ΔMAE vs same-source aggregate +3 to +8 kg/ha in 5 of 6 tier × model cells; significantly better only for XGB/Ridge with last-season context (≈1-2 %) |
| Is the week *order* used? (H1b) | **No** for tree models (shuffled weeks do as well or better) and for LSTM/GRU in the anomaly formulation; weather itself does help the networks (≈1.5 %) |
| Does timing carry structured signal? (H2) | **Yes (explanatory):** equal-weekly-effects rejected, p = 3×10⁻⁸; largest effects in the last two pre-harvest weeks and panicle initiation |
| Does the calendar window matter? (H3) | **Yes:** placebo windows moved ≥ 6 weeks earlier are worse |
| Can structure rescue the lags? (E9) | **Partly:** pre-specified smooth 3-4-parameter lag profiles recover the skill lost by 16 free lags (-6 to -8 kg/ha) and slightly beat the seasonal total (RF 327.0 vs 329.0); modest, not robust to Holm/rolling origin (notebook 12) |
| How much can weather add? | ≈ 1.0 % (total) to 1.5 % (weekly) of the variance left after district and year effects; best weather model improves the no-weather baseline by 2.4 % |

### Added notebooks
`06` weather acquisition, QC and lag construction · `07` main ablation (9 representations × 3 formulations × 3 models × 5 seeds) · `08` controls, robustness, heterogeneity · `09` LSTM/GRU with shuffled-week and no-weather controls · `10` TreeSHAP, permutation importance, panel fixed-effects rainfall-response · `12` pre-specified structured/smooth lag models · `11` pipeline diagram, machine-computed hypothesis verdicts, master tables.

### Specifications (implemented in `src/`)
1. **Agro-climatic anchoring** (`src/crop_calendar.py`): harvest reference weeks 41-47 by zone.
2. **Causal 16-week lags** (`src/weather_features.py`): vectorised, with zero-look-ahead assertions and a poisoning test.
3. **Experiment engine** (`src/experiment.py`): feature sets F0-F8, three formulation tiers, controls, rolling origin, paired cluster bootstrap.
4. **Sequence models** (`src/sequence_models.py`, `src/sequence_experiment.py`): `RiceLSTM`, `RiceGRU`, validation-only early stopping.
5. **Explainability** (`src/explain.py`, `src/panel.py`): exact TreeSHAP, permutation importance, panel FE distributed-lag regression with Wald tests.
